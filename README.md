# RosterIQ

**Every season fully staffed. Every rupee saved.**
Team Samlaun (AI-021) · AI-Tourism Hackathon 2026

RosterIQ is workforce intelligence for seasonal hill hotels in India. It:

1. **Builds a fair roster** from the occupancy forecast, respecting rest, weekly offs, leave and skills.
2. **Scores each person's workload risk** (a transparent 0 to 100 rule count, not a prediction) with plain-language reasons and the dates behind them: the burnout early warning.
3. **Suggests a fix** to the manager, applies it in one tap, and shows the roster, the score and the staff phone all change together.
4. **Counts the cost of quitting in rupees** (Home), as proof of what a lost team member costs. Revenue is a fixed seasonal subscription.

It is a front-end-only prototype: no backend, no accounts, everything runs in the browser.

**Live demo:** <https://rosteriq-xi.vercel.app>

## Run it

Needs Node 20 or newer.

```bash
npm install
npm run dev        # http://localhost:5173
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Type-check (`tsc -b`) then production build into `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm test` | Vitest suite (engine, risk, fixes, savings, staff app, tour) |
| `npm run typecheck` | TypeScript only |
| `npm run check` | Type-check, tests and build in one go |
| `npm run demo` | Prints a sample roster, three risk scores and the savings in the terminal |

Stack: Vite, React 19, TypeScript, Tailwind CSS v3, Framer Motion, Zustand, React Router, Vitest.

## The guided demo (about 4 minutes)

Press **Start** on the welcome screen, then **Start demo** (top right) or press **D** at any time.
The tour resets everything to the original state, then spotlights six moments:

1. **Season Readiness**: the one number an owner wants.
2. **The roster, Before and After**: paper roster against RosterIQ, with the overtime meter.
3. **Early warnings with reasons**: Ravi, Meena and Arjun, each at risk in a different way.
4. **Apply Ravi's fix**: the ring walks from 77 (high) to 47 (watch), a colleague covers his shifts.
5. **Team dashboard**: everyone at a glance, with Ravi's new score.
6. **Ravi's phone**: his weekly off is now fixed, with a note from his manager; it switches to Hindi.

Keys: `→` next · `←` back · `Esc` exit · `D` start or stop. **Reset demo** (left rail, or "Reset and restart" in the tour) restores the original state in one click.

## What is real, and what is sample data

**Real, and tested (99 tests):**

- **The roster engine** (`src/engine/`): demand from occupancy, a greedy day-by-day roster scored on fairness, overtime and preferences, then local repair (swaps, ejection chains, capped overtime). Hard rules (11 hours of rest, 6 days maximum, weekly off, approved leave, skills, first aid on site) live in one place, `constraints.ts`. It is deterministic and runs in about a third of a second.
- **The manual baseline**: "a manager writing it on paper" is generated by real code with no rest, streak or overtime checks. Its rule-breaks and overtime are genuine results, not staged ones.
- **The workload risk score**: a transparent rule count (days without a weekly off, overtime, late nights, short turnarounds, ignored leave, no skill growth, falling feedback). Every point has a reason and the dates behind it. It is never called a prediction.
- **Fixes**: `recommendFix` and `applyFix` really move shifts to rested, skilled colleagues and re-score the person.
- **The team dashboard** (headcount, tenure, weekly hours, overtime, feedback, skills cover, leave, the searchable directory and each profile) is computed live from the same state as every other screen. Pay lines are assumptions on sample rates.
- **Swap fairness checks** in the staff app reuse the same hard rules as the roster.
- **The savings maths** (`computeSavings`) is real and tested in the engine, but it has no screen in this build.
- **How state flows**: a fix, a swap, a mood check-in or a finished course changes one shared state, so Home, Roster, At risk, and the staff phone always agree.

**Sample data and assumptions (not real):**

- **The hotel and the people.** "Deodar Heights (sample hotel)", 25 rooms, Mussoorie, and all 20 staff are fictional. Their six-week shift history is generated deterministically and seeded with personas (Ravi: no weekly off for 21 days; Meena: close then open; Arjun: stagnating).
- **The occupancy forecast, leave requests, feedback scores and last season's resignations.**
- **Every rupee figure.** Hourly rates, the cost of an exit (about ₹30,000), the current overtime bill (₹20,000 a month), exits per year, exits prevented, the ₹2,499 monthly subscription, and the assumption that 45% of overtime comes from how rosters are written. All are labelled "sample" or "assumption".
- **The demo clock.** "Now" is fixed at Tue 13 Oct 2026, 9:00 am.
- **Prototype shortcuts.** A swap partner accepts automatically. Nothing is saved between page loads, sent anywhere or stored on a server.
- **Hindi text** was written by the team for the demo and should be reviewed by a native speaker before real use.

Any savings figure is a projection. Savings are never used to calculate the bill.

## Where things live

```
src/engine/    pure TypeScript, no UI: demand, roster, constraints, baseline, risk, fixes, savings
src/data/      the fictional hotel, staff, history and forecast
src/lib/       demo state (fixes, swaps, check-ins, courses), formatting, view helpers, Hindi text
src/store/     Zustand stores (app state, guided tour)
src/pages/     Home, Roster, At risk, Team dashboard, Staff app, 404
src/components UI kit, roster grid, risk ring and timeline, phone app, team charts and profile, tour, welcome
scripts/       demo.ts (terminal demo)
```

Money is always in rupees with lakh formatting (₹1.62 lakh) through `formatINR` and `formatLakh` in `src/lib/format.ts`.

## Deploy (static hosting)

It is a plain static build (`dist/`) with client-side routing, so any static host works. `vercel.json`, `netlify.toml` and `public/_redirects` already send every path to `index.html`.

### Vercel

```bash
npm install -g vercel     # once
vercel login              # once
vercel deploy --prod      # from the project folder; accept the defaults
```

Or from the dashboard: **Add New, Project, import the repository**; framework **Vite**, build command `npm run build`, output directory `dist`. No environment variables are needed.

### Netlify

- **Drag and drop:** run `npm run build`, then drag the `dist/` folder onto <https://app.netlify.com/drop>.
- **From Git:** **Add new site, Import an existing project**; build command `npm run build`, publish directory `dist`. `netlify.toml` already says so.
